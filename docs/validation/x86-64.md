# x86-64 Build and Compatibility

Strife must build and test on x86-64 so development is not locked to ARM.

## CI

GitHub Actions (`.github/workflows/ci.yml`) runs on `ubuntu-latest` (x86-64) with:

- PostgreSQL 17 service
- `cargo fmt --check`
- `cargo clippy --workspace --all-targets --target x86_64-unknown-linux-gnu -D warnings`
- `cargo build --workspace --target x86_64-unknown-linux-gnu`
- `cargo test --workspace --target x86_64-unknown-linux-gnu`
- Frontend `npm ci`, lint, format check, and production build

## Local release build

```sh
rustup target add x86_64-unknown-linux-gnu
# Native Linux x86-64:
cargo build --release --workspace --target x86_64-unknown-linux-gnu

# From macOS, use cross or a configured GNU linker (see docs/development/cross-compilation.md):
cargo build-x86-64-linux
# or
cross build --workspace --release --target x86_64-unknown-linux-gnu
```

## Docker Compose on x86-64

```sh
docker compose -f docker-compose.dev.yml up -d --wait
export DATABASE_URL=postgresql://strife:strife-dev@127.0.0.1:5432/strife
cargo test --workspace
```

Images are multi-arch; Docker Desktop on Intel/AMD macOS or Linux hosts pulls `linux/amd64` variants.

## Frontend

```sh
npm --prefix apps/web ci
npm --prefix apps/web run lint
npm --prefix apps/web run build
```

No architecture-specific frontend code paths.
